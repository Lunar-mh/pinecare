# 银伴全域智慧照护平台 - 统一规范验收清单与部署指南

## 1. 部署与答辩沙盘
为了保障答辩阶段项目的流畅运行，请评审和现场人员参照以下顺序启动整个系统。

### 1.1 依赖安装
需在四个子目录下分别执行安装。推荐使用 `Node 18+`，前端编译可使用 `Node 20+`。
```bash
cd backend && npm ci
cd frontend && npm ci
cd admin && npm ci
cd volunteer && npm ci
```

### 1.2 基础设施
我们需要依赖 MySQL 8.0 以及 Redis 等周边缓存来保障系统的存根运行策略。
只需在根目录一键启动：
```bash
docker-compose up -d mysql backend
```

### 1.3 预置演示种子
后台运行完毕后，注入专为竞赛和答辩设计的种子数据（已全部脱敏处理）。
```bash
cd backend
npm run migrate
npm run smoke:fresh-install
```

## 2. API 验收基线
为了保证后端接口的严谨性，项目组确定了以下统一响应规范：
- [x] 所有 API 都统一采用 HTTP 强状态码并辅以业务 JSON 报文 `{ code, message, data }` 的形式。
- [x] 正确响应：`code: 0`。
- [x] 跨域资源共享（CORS）与身份令牌（JWT）在全局拦截并进行了完善的错误边界隔离。
- [x] 真实的上游服务端与代理降级机制已全部统一（涉及AI、短信、医疗网关，可在日志审查运行时态）。

## 3. 已知遗留情况（Release Known Issues）
- **小程序包体积**：开发期间由于引入过多样板库，主包存在临界超标风险，我们在构建阶段通过分包挂载解决。
- **打包警告**：小程序编译过程中可能出现 `mini-css-extract-plugin` 对 CSS 顺序的警告（非阻塞，已确认无副效果），预计下个底层版本跟进。
- 目前后台默认开放以 `http://127.0.0.1:3001` 作为统一基线，请确保您的演示机器该端口未被占用。
