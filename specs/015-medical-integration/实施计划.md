# 实施计划: 医疗资源整合

**分支**: `015-medical-integration` | **日期**: 2025-07-18 | **规格**: `specs/015-medical-integration/`

## 概述
银伴平台医疗资源整合模块，对接外部医疗资源，提供在线问诊、预约挂号、检查报告查询、处方管理等功能。前端采用Taro跨端框架，后端采用Node.js + Express + MySQL + 第三方医疗API。

## 技术背景
**语言/版本**: Node.js 18.x, Express 4.x, MySQL 8.0  
**主要依赖**: Taro 4.x (前端), Express (后端), mysql2, axios  
**存储**: MySQL (医疗数据)  
**Target Platform**: 微信小程序  
**Project Type**: 移动端小程序 + 后端API服务  

## 跨模块依赖

- 当前实现计划未定义对其他业务模块（001-015）的强依赖（按模块内自包含服务规划）。
- 若后续需要复用其他模块的数据/接口（如统一鉴权、绑定关系、健康档案摘要等），必须在此补充：依赖模块、数据/接口契约、失败语义，并同步更新 tasks.md。

## 指标口径与观测

- **响应时间**：默认以 p95 口径度量；起止点为“网关/服务入口接收请求”到“返回响应”的服务端耗时。
- **成功率**：以业务成功码（如 `code=0`）与 HTTP 状态码综合统计；需明确计入/排除的失败类型。
- **外部依赖**：第三方 API 超时/限流/不可用应单独计数，并在错误语义中区分。
- **审计与隐私**：访问敏感数据的关键行为需记录审计日志；日志字段需脱敏。

## 第三方API接入决策（待确认）

**供应商候选**：
1. **平安健康（好医生）**：接口文档完善，支持图文/视频问诊，有开放平台API；推荐优先评估
2. **微医互联网医院**：覆盖面广，支持预约挂号；需申请企业合作接入

**接入前必须明确**：
- 供应商名称及官方API文档URL
- 鉴权方式（OAuth 2.0 / API Key）
- 数据返回格式（JSON schema）
- QPS限制与计费方案
- 医疗器械/互联网医院资质要求

> 在供应商确认前，任务 T001–T036 中涉及 `thirdPartyMedicalService.js` 的实现应先完成接口抽象层，不写死具体URL和鉴权逻辑。
