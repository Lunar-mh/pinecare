# 实施计划: 家庭空间

**分支**: `012-family-space` | **日期**: 2025-07-18 | **规格**: `specs/012-family-space/`

## 概述
银伴平台家庭空间模块，连接老人与家属的情感纽带。提供语音留言、电子相册、远程视频、代际互动激励等功能。前端采用Taro跨端框架，后端采用Node.js + Express + MySQL + OSS。

## 技术背景
**语言/版本**: Node.js 18.x, Express 4.x, MySQL 8.0, OSS  
**主要依赖**: Taro 4.x (前端), Express (后端), mysql2, ali-oss  
**存储**: MySQL (互动数据) + OSS (媒体文件)  
**Target Platform**: 微信小程序  
**Project Type**: 移动端小程序 + 后端API服务  

## 跨模块依赖

- 当前实现计划未定义对其他业务模块（001-015）的强依赖（按模块内自包含服务规划）。
- 若后续需要复用其他模块的数据/接口（如统一鉴权、绑定关系、健康档案摘要等），必须在此补充：依赖模块、数据/接口契约、失败语义，并同步更新 tasks.md。

## 指标口径与观测

- **响应时间**：默认以 p95 口径度量；起止点为“网关/服务入口接收请求”到“返回响应”的服务端耗时。
- **成功率**：以业务成功码（如 `code=0`）与 HTTP 状态码综合统计；需明确计入/排除的失败类型。
- **外部依赖**：第三方 API 超时/限流/不可用应单独计数，并在错误语义中区分。
- **审计与隐私**：访问敏感数据的关键行为需记录审计日志；日志字段需脱敏。

## 数据隔离机制（设计决策）

**多租户隔离策略**：所有家庭空间数据表通过 `family_id` 外键约束实现逻辑隔离，禁止跨 `family_id` 访问。具体实现：
- `family_messages`、`family_albums`、`family_interactions` 表均含 `family_id NOT NULL` 字段
- 查询层强制附加 `WHERE family_id = ?` 过滤条件
- 家庭成员权限通过 `family_members` 表的 `role`（老人/家属）字段区分
- MVP 阶段不引入独立 Schema，使用同一数据库逻辑隔离即可满足需求
