# 实施计划: GPS定位追踪

**分支**: `014-gps-tracking` | **日期**: 2025-07-18 | **规格**: `specs/014-gps-tracking/`

## 概述
银伴平台GPS定位追踪模块，为家属提供老人实时位置查看、轨迹回放、电子围栏等功能。保障老人出行安全，防范走失风险。前端采用Taro跨端框架，后端采用Node.js + Express + MySQL + Redis。

## 技术背景
**语言/版本**: Node.js 18.x, Express 4.x, MySQL 8.0, Redis 7.x  
**主要依赖**: Taro 4.x (前端), Express (后端), mysql2, ioredis  
**存储**: MySQL (位置数据) + Redis (实时位置缓存)  
**Target Platform**: 微信小程序  
**Project Type**: 移动端小程序 + 后端API服务  
**Performance Goals**: 位置更新 <1秒, 轨迹查询 <3秒  

## 跨模块依赖

- 当前实现计划未定义对其他业务模块（001-015）的强依赖（按模块内自包含服务规划）。
- 若后续需要复用其他模块的数据/接口（如统一鉴权、绑定关系、健康档案摘要等），必须在此补充：依赖模块、数据/接口契约、失败语义，并同步更新 tasks.md。

## 指标口径与观测

- **响应时间**：默认以 p95 口径度量；起止点为“网关/服务入口接收请求”到“返回响应”的服务端耗时。
- **成功率**：以业务成功码（如 `code=0`）与 HTTP 状态码综合统计；需明确计入/排除的失败类型。
- **外部依赖**：第三方 API 超时/限流/不可用应单独计数，并在错误语义中区分。
- **审计与隐私**：访问敏感数据的关键行为需记录审计日志；日志字段需脱敏。

## 宪法检查
| 宪法原则 | 检查结果 | 说明 |
|----------|----------|------|
| 数据真实性 | ✅ PASS | GPS真实定位数据，禁止伪造或模拟位置信息 |
| 可落地优先 | ✅ PASS | 微信小程序主动触发定位模式，规避平台后台持续定位限制（宪法技术约束对应条款） |
| 中文优先 | ✅ PASS | 全程中文位置展示、围栏告警通知与操作界面 |
| 删繁就简 | ✅ PASS | 家属一键查看位置，老人一键分享；核心操作不超过2步 |
| 前后一致性 | ✅ PASS | 与001用户体系、005家庭成员绑定关系数据互通，位置授权状态与家庭成员关系绑定 |
| 分阶段交付 | ✅ PASS | MVP实时位置查看+电子围栏告警，后续迭代轨迹回放与异常分析 |
| 适老化设计 | ✅ PASS | 老人端一键分享位置（操作1步），家属端地图可视化展示，默认关闭保护隐私 |

> **隐私合规（NFR，非宪法原则）**：定位数据属于《个人信息保护法》敏感个人信息；仅经老人授权的绑定家属可查看；默认关闭，老人主动开启后生效；位置数据传输加密（HTTPS），访问行为审计留存30天。
