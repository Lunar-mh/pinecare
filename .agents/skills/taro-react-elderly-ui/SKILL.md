# 青松安护适老小程序跨端开发技能 (Taro React Elderly UI)

本技能专为**青松安护（PineCare）微信小程序端（`frontend/`）**量身定制。依托 Taro 4、React 18、NutUI React Taro (`@nutui/nutui-react-taro`) 与 `weapp-tailwindcss`，围绕“暖玉微晶·液态温润”设计语言实现符合国家适老化与无障碍标准的跨端体验。

---

## 1. 小程序分包与包体硬约束 (Package Size Guardrails)

微信小程序平台对包体积存在硬性上限：**主包 ≤ 2MB，单个分包 ≤ 2MB，整包 ≤ 20MB**。

### 1.1 架构分包规划
- **主包 (`src/pages/`)**：
  - 仅保留核心框架页面：首页 (`index`)、登录认证 (`login`)、个人中心 (`profile`)、角色切换 (`role-select`)、家属看板 (`dashboard` / `care`)。
- **五大业务独立分包 (`src/subpackages/`)**：
  - `health/`：健康档案、血压心率体征趋势、手动录入
  - `medication/`：用药日历、用药计划、服药打卡
  - `sos/`：一键求助、紧急联系人、跌倒告警倒计时
  - `location/`：GPS 实时定位、安全地理围栏
  - `settings/`：智能设备绑定、紧急联系人设置、隐私与关于
- **静态资源分包化**：
  - 各分包专用的图标与图片存放在对应分包目录下，严禁无关资源堆积在主包 `src/assets/`。

### 1.2 依赖引入禁忌
- **NutUI 按需引入**：严禁全量 import 组件库，仅导入实际使用的组件与图标子路径。

## 2. 老人模式与家属模式动态切换 (Dual-Mode Architecture)

| 维度 | 老人模式 (Elderly Mode) | 家属看护模式 (Family Mode) |
| :--- | :--- | :--- |
| **交互原则** | 极简、单屏 ≤ 3 核心卡片、零学习成本 | 监控全景、体征动态、趋势图表、告警时间线 |
| **基准字号** | ≥ 20px 正文，42px ~ 48px 大数字，底线 16px | 16px 清晰易读，重要卡片标题 ≥ 20px |
| **主屏布局** | 翡翠松青主卡、朱砂红 SOS 醒目按钮、今日服药卡 | 长辈健康风险总览、用药进度、位置围栏状态 |
| **硬件操作** | 一键测量与大字反馈，弱网容错 | 设备状态查看、电量与断连提醒 |

## 3. 适老化与暖玉微晶视觉规范

### 3.1 物理热区与大按钮规范
- **主行动按钮**：高度 **56px ~ 64px**，圆角 `16px ~ 24px`，配合轻微压感反馈。
- **次级辅助按钮**：高度不低于 **48px**，卡片间距 `16px+`，避免手指误触。

### 3.2 核心令牌（详见 `src/styles/tokens.scss` & `src/design/tokens.ts`）
- 画布底色：`#F8F6F0`（暖玉凝脂）
- 品牌主色：`#1F6B56`（翡翠松青，高对比度适老主色）
- 关怀辅助色：`#C86D3B`（暖栗琥珀）
- 紧急警示色：`#D33833`（朱砂朱雀）
- 正文主墨色：`#18221E`

## 4. 低功耗蓝牙（BLE）健康设备直连规范

面向血压计、血糖仪、智能手环等硬件设备：
1. **自动重连与超时控制**：扫描超时 10 秒，未发现设备时提供清晰白话引导与一键重试。
2. **状态机流转**：`DISCONNECTED` → `SCANNING` → `CONNECTING` → `DISCOVERING_SERVICES` → `READY_TO_MEASURE`。
3. **断连优雅恢复**：监听 `Taro.onBLEConnectionStateChange`，非预期断连静默重试最多 3 次，失败采用温和横幅提示而非阻塞弹窗。

- [ ] 主包与各分包编译后产物是否均在 2MB 安全红线以内？
- [ ] 老人模式下所有可点击元素是否均 ≥ 48px × 48px？
- [ ] 最小字号是否绝对坚守 ≥ 16px，正文是否保持在 18px ~ 20px？
- [ ] 蓝牙与位置权限拒绝时，是否有清晰的引导长者开启设置页的弹窗？
- [ ] 在弱网或断网时，是否有缓存的健康档案可供查看？
