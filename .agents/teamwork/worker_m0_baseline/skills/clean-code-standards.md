# 生产级代码规范与质量审查技能 (Clean Code Standards)

本技能为智能体与开发者提供业界高标准的**代码可读性、可维护性与质量自检准则**。

## 1. 意图显式与命名哲学
- 变量说明意图：禁止 `data1`, `temp`, `flag`，必须清晰表达业务含义（`activeUserList`, `isElderlyModeEnabled`）。
- 函数动作明确：使用“动词 + 名词”（`calculateDailyMedicationDosage`, `verifySmsVerificationCode`）。
- 杜绝魔数：所有特定业务数字、枚举、重试次数必须抽取为冻结常量对象（`Object.freeze`）。

## 2. 复杂度控制与精简函数
- 单一职责：函数体建议 30 ~ 50 行，只做一件事。
- 圈复杂度红线：单个函数圈复杂度必须 ≤ 10。
- 嵌套深度限制：嵌套层级不得超过 3 层。
- 卫语句（Guard Clauses）优先：使用提前返回平铺主干逻辑，杜绝深层阶梯式 `if-else`。
- 策略查表法：分支大于 4 个时强制使用对象映射替代长 `switch-case`。

## 3. 防御性编程与异常处理
- 严禁空的 `catch (e) {}` 吞噬异常，必须记录结构化错误日志。
- 可选链 `?.` 与空值合并 `??` 进行深度安全访问。
- 不可变性优先：避免直接原地修改参数（In-place mutation），优先解构与纯函数映射。

## 4. 日志脱敏与隐私合规
- 手机号保留前 3 后 4 位（`138****1234`）。
- 身份证号保留前 6 后 4 位。
- 密码、Token、密钥在进入日志前统一覆写为 `[REDACTED]`。

## 5. ESLint 与格式规范
- 执行 `npm run lint` 必须满足零警告（`--max-warnings=0`）。
- 遵循单引号、两空格缩进、100字符换行规范。
