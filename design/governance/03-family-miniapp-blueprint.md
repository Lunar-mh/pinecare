# 家属端小程序蓝图

## 1. 端定位

家属端不是老人端的翻版，而是“远程守护与协同决策入口”。其核心问题不是“我能浏览多少数据”，而是“我现在是否需要处理什么问题”。

竞赛阶段，家属端必须围绕链路 B、链路 C 展开。

## 2. 家属端目标任务

1. 快速看到长辈是否存在风险
2. 快速查看位置、SOS、异常指标、未完成用药
3. 进入家庭空间维持陪伴关系
4. 在需要时协调社区或医疗资源

## 3. 信息架构

### 首页优先顺序

1. 风险事件
2. 异常指标
3. 未完成用药
4. 定位状态
5. 家庭互动
6. 服务协同入口

### 服务页分组

1. 监护中心
2. 家庭互动
3. 服务协调

### 我的页分组

1. 家庭关系
2. 守护设置
3. 支持与关于

## 4. P0 功能清单

1. 长辈状态总览
2. 位置共享查看
3. SOS 事件查看与感知
4. 用药进度查看
5. 家庭空间互动

## 5. P1 功能清单

1. 医疗资源协同
2. 社区服务触达
3. 时间银行协作入口

## 6. 家属端依赖 API 范围

1. `family`
2. `health-archive`
3. `medication`
4. `sos`
5. `gps`
6. `family-space`
7. `medical`
8. `time-bank`

规则：

1. 家属端接口必须围绕“已绑定老人”
2. 家属端只能读取自己有权限的老人范围
3. 家属端不能看到社区全局台账

## 7. 交互原则

1. 默认展示“是否需要我处理”
2. 一切高优先内容都必须比内容互动更靠前
3. 地图、健康、用药、SOS 的入口必须尽量短路径直达
4. 家属端不能堆满配置项，复杂规则留给后台

## 8. 家庭互动边界

家庭空间只承担以下能力：

1. 照片互动
2. 留言互动
3. 轻陪伴行为记录
4. 正向激励或积分展示

不承担以下能力：

1. 长链 IM 聊天
2. 复杂社交关系扩展
3. 多群组社交产品化

## 9. 演示脚本要求

家属端必须支持以下答辩演示：

1. 查看长辈首页状态
2. 查看当前位置与安全状态
3. 感知 SOS 事件
4. 查看今日用药进度
5. 进入家庭空间发送或查看互动内容

## 10. 禁做项

1. 不做泛家庭社交平台
2. 不做长辈全量后台数据管理
3. 不做跨家庭复杂权限配置
