# 志愿者端蓝图

## 1. 端定位

志愿者端是轻量任务执行端，不承担社区审核与全局管理职责。它的目标是让志愿者快速知道自己今天要做什么、现在该做什么、做完如何确认。

竞赛阶段，志愿者端必须主要服务链路 D。

## 2. 目标用户

1. `volunteer`

## 3. P0 功能清单

1. 今日任务总览
2. 待接单
3. 进行中
4. 待确认
5. 签到签退
6. SOS 协助任务
7. 工时记录
8. 培训提醒

## 4. P1 功能清单

1. 服务成长
2. 志愿者评级
3. 排班确认
4. 时间银行贡献可视化

## 5. 界面结构建议

推荐保留三个主标签：

1. 首页
2. 任务
3. 我的

首页只显示：

1. 今日待办
2. 今日工时
3. 紧急协助
4. 培训通知

## 6. 志愿者端依赖 API 范围

1. 新增 `volunteer` 命名空间，承担志愿者自服务接口
2. 部分任务详情可由 `community` 域提供管理侧视角接口
3. 工时、签到签退、培训状态、成长记录应尽量收敛到志愿者域

规则：

1. 志愿者端只能访问与自己任务相关的数据
2. 不得浏览老人全量隐私档案
3. 不得调用社区管理员操作接口

## 7. 交互原则

1. 按任务状态组织，而不是按功能组织
2. 尽量降低填写与配置负担
3. 让接单、签到、完成、确认形成最短操作路径
4. 所有紧急协助入口必须更靠前

## 8. 演示脚本要求

志愿者端必须支持以下演示：

1. 查看今日任务
2. 接单或开始服务
3. 进行签到
4. 完成服务并进入待确认
5. 查看工时更新
6. 可选展示时间银行贡献变化

## 9. 禁做项

1. 不做社区后台同质功能
2. 不做老人档案全量浏览
3. 不做系统配置、审核、活动发布
4. 不在竞赛阶段扩写成复杂工作台产品
