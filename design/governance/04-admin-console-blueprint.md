# 社区管理后台蓝图

## 1. 端定位

社区管理后台是银伴的风险处置中心、运营协同中心和答辩证据展示中心。它一方面要支撑真实业务流程，另一方面要在比赛场景中承担“全局可视化证明”的角色。

## 2. 目标用户

1. `community_admin`
2. `super_admin`

后台不面向老人和家属。

## 3. P0 功能清单

1. 今日工作台
2. 用户管理
3. 家庭绑定管理
4. 健康监管
5. 用药监管
6. SOS 风险中心
7. GPS 风险中心
8. 社区运营看板

## 4. P1 功能清单

1. 跌倒检测专题
2. 药物风险专题
3. 医疗资源网络
4. 时间银行审核
5. 志愿者管理

## 5. 页面组织原则

后台页面按“问题中心”组织，而不是按“数据库表”组织。

推荐导航分层：

1. 态势总览
2. 人员与关系
3. 照护与风险
4. 社区运营

## 6. 首页工作台必须展示的内容

1. 今日关键指标
2. 风险事件列表
3. 待处理任务
4. 今日服务或活动概览
5. 志愿者与工单状态摘要

## 7. 后台依赖 API 范围

1. `admin`
2. `community`
3. `statistics`
4. `health-archive`
5. `medication`
6. `sos`
7. `gps`
8. `fall-detection`
9. `drug-interaction`
10. `medical`
11. `time-bank`
12. `family`

规则：

1. 后台接口面向社区范围或全局范围
2. 必须包含作用域校验
3. 用于审核、监管、分派、统计和演示

## 8. 后台的答辩价值

后台不是只为管理人员准备，也承担三项比赛价值：

1. 展示项目不是单端小程序
2. 展示风险、任务、统计闭环
3. 展示平台型而非工具型系统能力

## 9. 演示脚本要求

后台必须支持以下演示：

1. 进入工作台查看今日态势
2. 查看用户与家庭绑定
3. 查看健康与用药监管
4. 进入 SOS 风险中心处理事件
5. 查看 GPS 风险与社区运营看板
6. 可选展示志愿者和时间银行专题

## 10. 禁做项

1. 不在竞赛阶段引入复杂 BI 平台
2. 不引入低代码配置平台
3. 不开发长审批流引擎
4. 不把后台做成企业 ERP
