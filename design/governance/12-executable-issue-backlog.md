# 四端协同可执行 Issue 清单

## 1. 使用说明

本文档把前面的总规、蓝图和任务拆解继续压实成“可直接执行的 issue backlog”。每个 issue 都按以下维度描述：

1. 所属端
2. 优先级
3. 关联主链路
4. 前置依赖
5. 交付物
6. 完成标准

执行顺序规则：

1. 先做后端基础边界，再做前台主链路页面
2. 先做老人端、家属端、后台的主闭环，再做志愿者端
3. 医疗、时间银行、药物风险等作为增强项排在主闭环之后

## 2. 老人端 Issue 清单

优先级：P0  
主链路：A

## 8. 每条 Issue 的统一验收模板

每个 issue 完成时都必须提交以下五项说明：

1. 该 issue 服务于哪条主链路
2. 影响了哪些页面或接口
3. 涉及哪些角色和权限
4. 增加了哪些测试或最小验证
5. 是否影响答辩口径与演示脚本
