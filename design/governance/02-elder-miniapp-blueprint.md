# 老人端小程序蓝图

## 1. 端定位

老人端是“低认知负担的日常照护入口”，核心任务是帮助老人完成每天最重要的照护动作，而不是给老人展示过多系统功能。

竞赛阶段，老人端必须围绕链路 A、链路 B 构建。

## 2. 页面架构

### 主包页面

1. 登录页
2. 首页
3. 服务页
4. 我的页

原则：

1. 主包只保留高频入口与壳层页面
2. 复杂业务页面全部进入分包

### 分包页面

1. 健康档案
2. 用药提醒
3. SOS
4. 语音助手
5. 家庭空间
6. AI 伴聊
7. 药物风险
8. 定位共享
9. 医疗资源
10. 设置、设备、紧急联系人

## 3. 用户任务模型

老人端所有页面都应服务于以下用户任务：

1. 我今天身体状态怎么样
2. 我今天要吃什么药，是否已经吃过
3. 出现危险时我如何一键求助
4. 我怎么和家人产生轻互动
5. 我如何用最少操作完成事情

## 4. 信息优先级

首页必须按以下顺序组织信息：

1. 今日关键状态
2. 今日待办用药
3. 高频快捷操作
4. 陪伴与服务入口

禁止以下情况：

1. 首页堆满全部模块入口
2. 把资讯、宣传、弱相关内容放在风险与待办之前
3. 把复杂设置放在老人端高层路径

## 5. P0 功能清单

1. 登录与身份进入
2. 首页总览
3. 健康总览与趋势
4. 今日用药与确认
5. SOS 触发与取消
6. 语音入口
7. 家庭空间轻互动
8. 我的页中的设备、紧急联系人、设置

## 6. P1 功能清单

1. AI 伴聊
2. 药物相互作用查询
3. 定位共享设置
4. 医疗资源入口

## 7. 交互原则

1. 一屏只保留少量核心操作区
2. 风险、提醒、待办优先于内容展示
3. 文字要短、按钮要大、动作要明确
4. 可触控即可完成，也允许语音并行
5. 高风险动作必须有明显确认或反馈

## 8. 依赖 API 范围

老人端主要依赖以下 API 分组：

1. `auth`、`user`
2. `health-archive`
3. `medication`
4. `sos`
5. `voice`
6. `family-space`
7. `ai-companion`
8. `drug-interaction`
9. `gps`
10. `medical`

规则：

1. 老人端接口必须面向“我的数据”和“我的动作”
2. 不允许让老人端请求社区全局数据
3. 不允许让老人端承担后台审核任务

## 9. 关键状态流转

### 用药任务

1. `pending`
2. `taken`
3. `missed`
4. `skipped`

### SOS 事件

1. `triggered`
2. `responding`
3. `resolved`
4. `cancelled`

所有状态必须与共享后端字典一致，不允许前端自造状态文案。

## 10. 演示脚本要求

老人端必须支持以下答辩演示：

1. 登录进入首页
2. 查看今日状态与未完成用药
3. 进入用药页确认服药
4. 返回首页看到状态更新
5. 触发 SOS，展示风险链路起点

## 11. 禁做项

1. 不做泛娱乐内容广场
2. 不做商城
3. 不做复杂社交聊天
4. 不做需要老人理解复杂业务状态的后台式页面
