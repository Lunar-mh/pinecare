# 跨端主链路验收矩阵

## 1. 使用说明

本矩阵用于约束开发、联调、录屏和答辩。任何被视为“已完成”的链路，都必须能在此矩阵中找到页面、接口、角色、证据和测试支撑。

## 2. 链路 A：老人日常健康与用药闭环

目标：证明老人端具备日常照护核心价值。

涉及端：

1. 老人端
2. 共享后端
3. 可选后台监管视角

必备页面：

1. 登录页
2. 老人首页
3. 健康总览页
4. 用药页

必备接口：

1. 登录
2. 今日健康摘要
3. 今日用药任务
4. 用药确认

完成标准：

1. 老人可登录并进入首页
2. 首页能显示今日状态与待办用药
3. 用药确认后首页数据刷新
4. 后台可选查看到相应用药变化

## 3. 链路 B：老人 SOS -> 家属感知 -> 社区处置

目标：证明银伴具备真正的平台型风险闭环。

涉及端：

1. 老人端
2. 家属端
3. 社区后台
4. 共享后端

必备页面：

1. 老人端 SOS 页
2. 家属端首页或事件入口
3. 后台 SOS 风险中心

必备接口：

1. 触发 SOS
2. 获取 SOS 事件
3. 状态流转更新
4. 通知状态回写

完成标准：

1. 老人端可触发事件
2. 家属端能看到风险感知
3. 后台能查看并流转事件
4. 事件最终关闭并可追溯

## 4. 链路 C：家属远程守护与家庭互动

目标：证明家属端不是被动查看，而是形成陪伴证据。

涉及端：

1. 家属端
2. 老人端
3. 共享后端

必备页面：

1. 家属首页
2. 位置页
3. 家庭空间页

必备接口：

1. 已绑定老人状态查询
2. 定位与围栏状态
3. 家庭空间消息或相册接口

完成标准：

1. 家属可查看长辈状态
2. 可查看位置状态
3. 可进入家庭空间形成互动

## 5. 链路 D：社区任务 -> 志愿者执行 -> 状态回写

目标：证明社区协同与执行闭环存在。

涉及端：

1. 社区后台
2. 志愿者端
3. 共享后端
4. 可选时间银行视角

必备页面：

1. 后台任务或志愿者管理页
2. 志愿者首页
3. 志愿者任务页

必备接口：

1. 创建或分派任务
2. 志愿者获取我的任务
3. 接单
4. 签到签退
5. 完成任务
6. 工时或时间银行状态回写

完成标准：

1. 后台可分派任务
2. 志愿者端可接单并签到
3. 完成后状态更新
4. 工时或贡献记录可见

## 6. 链路 E：医疗连接闭环

目标：证明项目具备医疗资源接入方向，而不是孤立工具。

涉及端：

1. 老人端或家属端
2. 后台
3. 共享后端

必备页面：

1. 医疗资源入口
2. 咨询或预约页
3. 报告查看页

必备接口：

1. 医疗目录查询
2. 在线咨询启动
3. 预约创建
4. 报告同步

完成标准：

1. 至少可以在 stub 模式稳定演示
2. 能明确解释 live 模式的真实边界
3. 后台或家属端能看到相关结果

## 7. 统一验收规则

1. 每条链路至少要有一条完整录屏脚本
2. 每条链路至少要有一组后端测试或回归证据
3. 每条链路都要说明哪些是已实现、哪些是 stub、哪些是待真实接入
