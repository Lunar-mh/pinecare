# 共享后端蓝图

## 1. 总定位

共享后端是四端唯一业务中枢，负责：

1. 认证与鉴权
2. 数据聚合
3. 业务编排
4. 第三方适配
5. 定时任务
6. 审计记录
7. 演示模式切换

竞赛阶段明确不做：

1. 微服务拆分
2. 第二套后端
3. 大规模消息中间件重构

## 2. 保留的统一规范

1. 统一响应结构：`{ code, message, data }`
2. Controller -> Service -> Model 分层
3. 业务错误使用带 `code` 与 `statusCode` 的异常
4. 路由前缀继续沿用现有模块命名
5. `stub/live` 双模式继续保留

## 3. 领域划分

### 基础身份域

1. `auth`
2. `user`
3. 家庭关系
4. 紧急联系人
5. 设备绑定

### 老人照护域

1. 健康档案
2. 健康记录
3. 用药计划
4. 用药日志
5. 药物风险
6. 语音助手
7. AI 伴聊

### 安全响应域

1. SOS
2. 定位
3. 围栏
4. 跌倒检测
5. 告警通知

### 协同服务域

1. 家庭空间
2. 社区
3. 志愿者任务
4. 时间银行
5. 服务工单

### 医疗连接域

1. 医疗目录
2. 在线咨询
3. 预约
4. 报告同步

### 运营支撑域

1. 统计
2. 审计
3. 演示场景
4. 第三方诊断
5. 内容安全

## 4. API 分层规则

### 前台接口

面向老人端、家属端、志愿者端，特点：

1. 只返回“我的任务”“我的关系”“我的数据”
2. 只允许在授权范围内读写
3. 不承担社区全局查询

### 后台接口

面向社区管理员与超级管理员，特点：

1. 返回社区范围或全局范围的汇总视角
2. 必须包含作用域校验
3. 用于审核、监管、分派、统计和演示

## 5. 志愿者接口策略

后续新增志愿者自服务能力时，必须新增独立 `volunteer` 命名空间，用于：

1. 我的任务
2. 接单
3. 签到签退
4. 工时记录
5. 我的培训状态
6. 我的成长记录

社区管理员管理志愿者的能力仍保留在 `community` 或 `admin` 侧。

## 6. 演示模式策略

共享后端必须同时支撑：

1. 竞赛演示模式
2. 真实接入预留模式

规则：

1. 所有第三方调用都必须在服务层封装
2. `stub` 模式必须稳定、可回放、可解释
3. `live` 模式失败时必须能返回清晰原因，不可假装成功

## 7. 审计与诊断

后端必须统一记录以下操作：

1. 后台关键写操作
2. 风险事件处理
3. 任务流转
4. 演示种子导入
5. 第三方失败与降级

## 8. 后续 AI 的后端开发规则

1. 不允许绕过现有模块边界直接在 Controller 中写业务细节
2. 不允许新建孤立工具路由
3. 不允许新增没有角色约束的写接口
4. 不允许为单次演示硬编码破坏通用数据结构
5. 不允许新增状态值而不同步字典与测试
