# 防跑偏清单

本清单用于约束后续 AI 与开发者，避免项目在实现过程中偏离竞赛主线。

## 1. 产品方向防跑偏

1. 不把银伴做成泛健康 App
2. 不把银伴做成泛社交产品
3. 不把银伴做成养老商城
4. 不把银伴做成企业 ERP
5. 不把银伴做成纯 AI 聊天产品

## 2. 功能范围防跑偏

1. 不平均扩写全部 15 个模块
2. 不为了“看起来丰富”新增无主链路归属页面
3. 不把加分模块放在主链路之前
4. 不为了答辩炫技引入复杂但无证据价值的技术

## 3. 架构防跑偏

1. 不拆微服务
2. 不重写技术栈
3. 不新增第二套权限体系
4. 不在前端直接依赖第三方业务结果
5. 不绕过现有模块路由随意造新接口

## 4. 叙事防跑偏

1. 不把设计稿说成上线产品
2. 不把 stub 说成真实医院接入
3. 不把单次演示数据说成真实试点成效
4. 不把测试通过说成市场验证完成

## 5. 开发前必答五问

每次新开发前，必须先回答：

1. 这个改动服务于哪条主链路？
2. 属于哪个端？
3. 面向哪个角色？
4. 依赖哪些实体和接口？
5. 对答辩或落地证据有什么价值？

只要有一个问题回答不清，就不应立即进入开发。

## 6. 提交前必查五项

1. 是否破坏了角色权限边界
2. 是否新增了未登记状态值
3. 是否和总规、分端蓝图冲突
4. 是否影响了演示脚本稳定性
5. 是否把非真实能力包装成真实落地能力
