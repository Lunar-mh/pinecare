本设计系统用于微信小程序（Taro 4.x，React语法）“银伴”。

## 1. 适老化与无障碍（硬约束）

1) 字号（大字报表可视化界面元素规范）
- 正文：≥20sp
- 标题：≥28sp
- 数据数值：≥36sp
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L1272）

2) 对比度
- 普通文本：文字与背景对比度 ≥7:1（WCAG AAA）
- 最低门槛：≥4.5:1
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L1273 与 #L3163）

3) 点击/触控热区
- 最小点击区域：≥44×44px
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L3164）
- 主操作焦点：≥60×60（pt/px等效）
（来源：工信部《移动互联网应用(APP)适老化通用设计规范》；细则后续在设计系统补充“条款编号/页面链接”作为证据，当前先作为硬约束执行）

4) 信息架构（单屏原则）
- 单屏信息流布局
- 核心功能入口以“**大图、大字、大按钮**”呈现
- 单屏显示不超过3个核心操作区
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L2411）

## 3. 语音交互UI（硬约束 + 兜底）

- 唤醒词："银伴银伴"
- 适老化语音合成：TTS语速 = 正常速度的0.8倍
- 针对听力特征优化频段：500-4000Hz
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L216-L217 与 #L2037）

失败兜底（必须提供）：
- 识别失败：给出大字提示 + 一键重试 + 可切换为“触控/文本输入”
- 权限被拒：明确说明原因 + 一键跳转设置（微信能力范围内）
- 播报中可打断（可见“停止播报”按钮，热区≥44×44）

## 4. 小程序平台约束（实现必须遵守）

- 小程序切后台后5秒内挂起
- 包体大小：主包≤2MB，分包≤2MB，总≤20MB
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L3304 与 #L3312-L3314）

分包策略（硬规则）：
- 主包：仅含首页 + Tab框架
- 六大功能模块：各为独立分包
（来源：`银伴_全域智慧照护平台_产品设计方案.md`#L3312）

## 5. 冲突规范的决策（优化点）

产品文档中同时出现：
- 严格版：正文≥20sp/标题≥28sp/数据≥36sp + 对比度≥7:1
- 最低版：正文≥18px/标题≥24px + 对比度≥4.5:1

决策（为“力求前端完美”的最简单有效方案）：
- 默认采用更严格的 20sp/28sp/36sp 与 7:1 作为目标；任何因平台/组件限制无法达到的场景，必须在页面规范中标注“例外原因+替代措施”，并确保不低于4.5:1与44×44px。
